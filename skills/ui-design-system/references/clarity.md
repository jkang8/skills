# Clarity for the user

Part of the ui-design-system rules; checklist item 6 checks against this file. Headline numbers, copy and buttons are in SKILL.md.

- Write for the least technical person who uses the screen. Every screen answers "what do I do next, and what is it worth?"
- One action leads per view.
- Counts reconcile across inbox, badges and tables. Group raw rows into tasks by cause; the rows become drill-down evidence.
- A list item is a specific title sentence (names, dates, numbers), one muted meta line (owner · due), the amount once, and one action ("Fix notes", not "Approve"). No labeled slots such as Happened / Impact / Next: specificity replaces labels.
- Progressive disclosure: IDs, codes, raw records and methods sit behind "Show details" or "How we got this". No unexplained acronym on default views.
- State trust and safety guarantees once, in one persistent place. Repeating them on every card reads as anxiety.
- Show progress and a done state (a running total, an empty inbox).
- Give different roles different views of the same data (summary vs work queue) when their jobs differ.
- Demos: lead with one concrete story, solve it end to end, and keep to about 60 seconds.
